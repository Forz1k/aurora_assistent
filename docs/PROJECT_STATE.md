## Задача 1.2 выполнена

Команда python -m aurora --chat открывает окно PySide6. Список моделей и ответ /api/chat запрашиваются в рабочем потоке; пользователь может обновить модели, отправить сообщение и продолжить беседу в том же окне. Ответ отображается после завершения генерации.

Добавлен aurora/ui/chat.py. Обновлены точка входа, провайдер Ollama, requirements.txt, README и этот файл. Для виджетов установлен PySide6-Essentials 6.8.3. Проверки: 10 тестов pytest прошли, pip check успешен. В тесте Qt offscreen выбрана qwen2.5:1.5b, нажата кнопка отправки и получен реальный ответ на 2 + 2. Тестовый сервер остановлен. Git читает origin, удалённых ссылок на момент проверки нет.

## Задача 1.3 выполнена — этап Ollama завершён

Чат выводит ответ по частям. «Остановить» разрывает соединение, возвращает вопрос для повтора и исключает незаконченный ответ из контекста. Ошибки соединения, формата и преждевременное завершение показываются в окне. История одной беседы хранится в SQLite и загружается при запуске. При недоступной базе чат показывает предупреждение.

Изменены aurora/ui/chat.py, aurora/providers/ollama.py, .gitignore, README.md и документы ARCHITECTURE, TESTS, PROJECT_STATE. Добавлены aurora/memory/history.py и tests/test_chat_stream.py. Все 11 тестов прошли, включая отмену, обрыв потока, повтор и восстановление истории. Через окно Qt с временной базой проверен реальный ответ qwen2.5:1.5b. Каталог data исключён из Git.

## Задача 2.2 выполнена

Созданы aurora/providers/openai_provider.py и tests/test_openai_provider.py. Обновлены документы ARCHITECTURE и PROJECT_STATE. OpenAIProvider принимает ключ и имя модели, передаёт контекст в Responses API, читает поток SSE, обрабатывает остановку, ошибки HTTP и незавершённые ответы. Используются существующие зависимости Qt.

17 тестов pytest прошли. Пять новых сценариев используют локальный HTTP-сервер с тестовым ключом. Доступ к реальному аккаунту и модели OpenAI не проверялся.

## Задача 2.3 выполнена — этап OpenAI завершён

Диалог «Провайдер…» переключает Ollama/OpenAI и позволяет ввести модель и заменить API-ключ. Провайдер и модель восстанавливаются из локального INI, ключ хранится в Windows Credential Manager. У каждого провайдера отдельная история. При ошибке чтения ключа пользователь может открыть настройки и восстановить доступ.

Добавлены aurora/security/credentials.py, aurora/ui/provider_dialog.py, tests/test_provider_settings.py. Изменены aurora/ui/chat.py, requirements.txt, README и этот документ. Добавлена зависимость pywin32 311. Проверки: 18 тестов прошли, pip check успешен. Через Qt и реальное хранилище Windows проверены сохранение и замена временного ключа, восстановление выбора и разделение историй. Тестовую запись удалили. Запрос к платному API с пользовательским ключом не выполнялся.

## Этап 3 · Задача 3.1 выполнена

Добавлены команды --list-mics и --check-mic. Доступны выбор входа через --device и длительность 1–60 с через --seconds. Модуль aurora/audio/input.py отдаёт блоки float32 PCM (моно, 16 кГц, 32 мс) и вероятность речи. Модель Silero загружается при захвате и работает на CPU. Аудио остаётся в памяти.

Изменены aurora/__main__.py, requirements.txt, README.md и этот файл; добавлены aurora/audio/input.py и tests/test_audio_input.py. Проверены Windows-сборки sounddevice 0.5.3 и silero-vad-lite 0.4.0. С MCHOSE V9 PRO и fifine получено по 32 блока, в этих коротких записях речь не обнаружена. На отдельно синтезированной фразе Windows SAPI реальный VAD отметил речь в 78 из 131 блоков. Недоступный вход даёт диагностическое сообщение. 20 тестов прошли, pip check успешен.
